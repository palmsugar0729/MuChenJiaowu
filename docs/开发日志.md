### 踩坑记录

1. **仓库改名** —— `salary-counter` → `MuChenJiaowu`，本地 remote 与手册 clone 地址同步更新
2. **`git clone <url> .` 末尾的点看不见** —— 看漏就多套一层目录，后续所有路径全废。手册改为显式绝对路径 + `ls` 验证
3. **SSH 私钥不在 `Downloads`** —— 实际在 `D:\密钥\`，`~/.ssh/config` 里 `jplearning` 那条路径一直是错的，用户一直以为在用密钥登录，其实每次都在敲密码
4. **Windows 私钥权限** —— `UNPROTECTED PRIVATE KEY FILE`。要 `icacls /remove` 删掉 `Authenticated Users`、`BUILTIN\Users` 两个**显式**权限；`/inheritance:r` 对显式权限无效。Git Bash 下还需 `MSYS_NO_PATHCONV=1`，否则 `/remove` 被当路径转换
5. **Git Bash 的 ssh 不检查 Windows ACL** —— 同一份 config，Git Bash 里连得上、cmd 里报错。**验证必须用 `C:\Windows\System32\OpenSSH\ssh.exe`**

### 关键决策

| 决策 | 理由 |
|---|---|
| `init_superadmin.py --name` 填**真实姓名** | 它是 `display_name`，会出现在审批记录、操作日志、导出表格里；系统用手机号登录，没有「用户名」概念 |

### 关键决策

| 决策 | 理由 |
|---|---|
| 桌面版**不删除**，整体迁入 `codes/desktop/` 冻结 | 用户每月靠它交报表，且与后端依赖方向冲突（PySide6 vs FastAPI），必须隔离虚拟环境 |
| 费率不单独建 `rates` 表，合并进 `classes` | 费率就是班级的属性，没有跨班级复用场景，单独建表只多一次 JOIN |
| 审计时间戳**存 UTC**（`sa_type=UTCDateTime`） | SQLModel 0.0.47 只支持这一种带时区的存法。绕过它要 hack 类型系统，不值得 |
| 测试用**每测试清表**而非 drop/create | 快得多，且表结构是 session 级的不用重建 |

### 踩坑记录

1. **索引建了两次** —— `Approval.status` 上既写了 `Field(index=True)`，又在 `__table_args__` 里建了同名 `Index("ix_approvals_status")`，`create_all` 直接报 `index already exists`。**两者只能留一个。**
2. **SQLModel 0.0.47 拒绝朴素 datetime** —— 报错要求带时区或标注 `NaiveDatetime`，但**这个类在新版里已经不存在了**（只剩 `UTCDateTime`）。
3. **`UTCDateTime` 不能直接当类型注解** —— 它是 SQLAlchemy 类型，pydantic 会报 `Unable to generate pydantic-core schema`。正确写法：注解仍写 `datetime`，用 `Field(..., sa_type=UTCDateTime)`。
4. **测试之间互相污染** —— 夹具硬编码同一个手机号，第二个测试就撞 `UNIQUE constraint failed: users.phone`。加了 autouse 清表夹具。

### 部署方案二次变更（同日晚）

用户提出：系统将来要**被公司买断**，服务器和后期运维仍由用户自己承担。据此改了部署方案。

| 项 | 原方案 | **新方案** |
|---|---|---|
| 服务器 | 与刷题背单词站共用现有 4核4G | **独立新服务器，2核2G / 40G / 3~5Mbps** |
| 域名 | `jiaowu.palmsugar.cn` 长期沿用 | **开发期沿用，交付期换公司企业备案域名** |

**改的原因**（三条，按硬度排）：
1. **数据隔离** —— 学生表含姓名、性别、是否成年、电话，属**未成年人敏感个人信息**（PIPL），不该与个人项目混跑
2. **故障隔离** —— 个人站挂了不该连带公司的考勤系统下线，反之亦然
3. **责任清晰** —— 买断后这是交付物，跑在独立机器上才说得清

**关键发现——「先用个人名义备案，以后再转公司」是条单行道**：

- 绝大多数省份**不支持个人备案 → 企业备案直接变更**，只能注销重备
- 注销重备期间**网站必须停摆**（域名无法访问境内服务器），审核 1~20 工作日
- **小程序被一起锁死**：小程序备案主体须与注册主体一致，主体变更同样要注销重备
- 「域名归我、备案用公司」也走不通——企业备案要求域名实名就是企业

→ **结论：现在什么都别注册**，开发期复用 `jiaowu.palmsugar.cn`（子域名无需单独备案），谈成后由公司注册 + 企业备案，一步到位。

**待确认**：企业备案通常要求备案主体与服务器账号实名主体一致。服务器在用户名下、备案主体是公司，能否用**授权委托书**通过——**买断谈判前问腾讯云备案客服**。

**✅ 切换成本几乎为零**：服务器全程不换，交付时只改一条 DNS 解析，不涉及数据迁移、不停服。这正是「现在就分开服务器」的最大收益。
