## 本次：首次上线 Web 前端（2026-11-12）

背景：生产后端停在 `f440e51`（2026-10-07），前端**从来没部署过** ——
`https://jiaowu.palmsugar.cn/` 一直是 nginx 默认的 Welcome 页。
数据库不用动（8 张表齐、`lessons.content` 在），`requirements.txt` 自 10-07 没变过。

---

### 第 1 步 · 后端：备份 → 拉代码 → 重启

```bash
ssh muchen
/srv/muchen/backup.sh
cd /srv/muchen/app
git pull
sudo systemctl restart muchen
curl -s https://jiaowu.palmsugar.cn/api/health
```

✅ 应该看到：`git pull` 从 `f440e51` 快进到 `4b41436`（或更新的）；
health 回 `{"status":"ok","app":"沐晨课程管理系统"}`。

再验一次「新接口真的上去了」（防「代码拉了但服务没重启」）：

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://jiaowu.palmsugar.cn/api/approvals/my
```

✅ 应该看到 `401`（没登录被拦）。**`404` = 还是旧代码。**

> `git pull` 连 GitHub 偶尔会断（`Recv failure` / `GnuTLS recv error`），重试一两次即可。
> **一直断就别耗了**，改用下面的「git 包」办法 —— 服务器在国内，访问 GitHub 不稳定是老问题。

**备用：不用 GitHub，直接传代码**

本地（Git Bash）打一个只含 `master` 的 git 包，传上去让服务器从包里拉：

```bash
cd "d:/WorkSpace/projects/mix/MuchenCourseManagement"
git bundle create "d:/WorkSpace/projects/mix/muchen.bundle" master
scp "d:/WorkSpace/projects/mix/muchen.bundle" muchen:/tmp/muchen.bundle
ssh muchen
cd /srv/muchen/app
git bundle verify /tmp/muchen.bundle
git pull /tmp/muchen.bundle master
rm -f /tmp/muchen.bundle
```

✅ 之后照常 `sudo systemctl restart muchen`，再做下面那两条 curl 检查。
包是**全量历史**，服务器缺多少都能补；文件名里带上 commit 短号（如 `muchen-4b41436.bundle`）好认。

### 第 2 步 · 传前端（在你自己电脑的 Git Bash 里跑）

```bash
ssh muchen 'rm -rf /tmp/web-dist'
scp -r "d:/WorkSpace/projects/mix/MuchenCourseManagement/codes/web/dist" muchen:/tmp/web-dist
ssh muchen 'mkdir -p /srv/muchen/web && rsync -a --delete /tmp/web-dist/ /srv/muchen/web/ && rm -rf /tmp/web-dist && ls /srv/muchen/web'
```

✅ 应该看到：`assets` 和 `index.html`。

> `/srv/muchen/web` **故意放在 git 仓库外面** —— 以后 `git pull` 不会碰它。

---

### 第 3 步 · Nginx 加 SPA 配置

```bash
sudo nano /etc/nginx/sites-available/muchen
```

在**第一个 `server { }`**（带 `listen 443 ssl` 的那个）里，`location /api/` **前面**插入：

```nginx
    # 前端：本地 npm run build 出来的静态文件，服务器不装 Node
    root /srv/muchen/web;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 发版后要立刻拿到新的 index.html（它引用的资源名带 hash）
    location = /index.html {
        add_header Cache-Control "no-cache";
    }
```

⚠️ `/api/` 那段**不要动** —— 前缀更长的 location 优先级更高，会自动接管 API 请求。

```bash
sudo nginx -t && sudo systemctl reload nginx
```

✅ 应该看到：`syntax is ok` / `test is successful`。
**报错就停下，把输出贴给我，别 reload。**

## 以后每次发版

前端（改了 `codes/web/`）：

```bash
cd "d:/WorkSpace/projects/mix/MuchenCourseManagement/codes/web"
npm run build
```

然后把上面**第 2 步**的三条原样再跑一遍（`rsync --delete` 会清掉旧资源）。

后端（改了 `codes/server/`）：只跑**第 1 步**的 `git pull` + 重启。
⚠️ 如果这版**动了表结构**，先看 `docs/Phase0-服务器操作手册.md` 里对应的迁移脚本，
不能只 pull。

### 2026-11-24 这版：多跑一个迁移脚本

`users` 加了 `failed_login_attempts` / `locked_until`（登录连错 5 次锁 1 小时的账）。
**顺序不能反** —— 先迁移、再重启，否则新代码查一个不存在的列会直接 500：

```bash
cd /srv/muchen/app
git pull
cd codes/server
.venv/bin/python scripts/migrate_add_login_lockout.py
cd /srv/muchen/app
sudo systemctl restart muchen
```

✅ 应该看到 `已给 users 加上：failed_login_attempts, locked_until`（重复跑会显示「跳过」/「无需改动」）。
**脚本是幂等的**，跑错了可以放心再跑一次。
