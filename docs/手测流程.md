# 第 1 节 · 登录与账号（A 组）

## A1 · 没登录时打开内页

**操作**：浏览器新开一个无痕窗口，地址栏输 `http://localhost:5173/students`

**应该看到**
- 跳到登录页，**地址栏变成** `.../login?redirect=/students`
- 标题「沐晨课程管理」，副标题「请使用手机号登录」
- 输对密码登录后，**直接落在「学生」页**，不是首页

## A2 · 超管首次登录被强制改密

**操作**
1. 手机号输 `13000000001`，密码输 `00000000`
2. 点「登录」
3. 在新密码框输 `muchen2026`，确认框再输一次
4. 点「确定修改」

**应该看到**
- 第 2 步之后**没有进系统**，而是进了改密页：标题「请先修改密码」，
  副标题「初始密码是系统生成的，请换成只有你自己知道的」，底部一行「首次登录必须修改密码后才能继续」
- 改完**自动进「课程」页**，底栏高亮「课程」
- 此时**刷新页面**，还是登录状态，不会再让你改密

> 💡 顺手试一下密码框右边的**眼睛图标**：点一下明文、再点一下变回圆点。登录页和这个页面都有。

## A3 · 改密的三种错误

在「我的」页 →「修改密码」里逐个试（**每试完一个都别真的改成功**，下面 3 个都是被拦下）：

| 情况 | 应该看到 |
|---|---|
| 两次新密码输得不一样 | 「两次输入的新密码不一致」 |
| 新密码只输 5 位 | 「新密码至少 6 位」 |
| 新密码跟原密码一样 | 「新密码不能和原密码相同」 |

**另外**：故意输错原密码 → 「原密码不正确」。
⚠️ 但**先别把次数用光** —— 连错 5 次账号会锁 1 小时（A8 专门测它）。

另外两件这一页要有的事（2026-11-24 加的）：

- **两次新密码不一致时，在「确认新密码」下面直接显示「密码不一致」** —— 不用等点「确定修改」
- **从「我的」进来时，页面顶部有返回键 `‹`**；**首次登录强制改密时没有返回键**（那条路不能退）

> 这两条容易看出区别：A2 那次进来没有返回键，这里从「我的」进来有。

## A4 · 登录密码错

**操作**：退出登录 → 重新输对的手机号 + **故意错的密码** → 登录

**应该看到**：「手机号或密码不正确，**还能再试 4 次**」。
再错一次，数字跟着往下走（3 次、2 次……最后是「只剩最后 1 次机会，再错就锁定 1 小时」）。
⚠️ **不能**被踢回登录页两次、也不能白屏 —— 这是最容易写错的地方（错误 401 不等于 token 过期）。

> 手机号不存在时也是同一句开头（不告诉外面「这个号存在」）。测的时候两者看着一样就对了。

## A5 · 建老师账号（在电脑上，走接口文档）

界面**没有**账号管理页，这一刻意用后台接口建号：

**操作**
1. `http://127.0.0.1:8000/docs` → 找到 `POST /api/admin/users` → 点「Try it out」
2. 先点右上角 **Authorize**，把超管的 token 填进去（token 怎么拿：先调 `POST /api/auth/login`，返回里的 `access_token`）
3. Request body **先把框里原有的内容全选删掉**，再贴：
   ```json
   { "phone": "13800000002", "display_name": "测试老师", "role": "teacher" }
   ```
4. 点 Execute

> ⚠️ **第 3 步的「先删掉」不能省**。`/docs` 默认给的示例值是
> `{"phone": "string", "display_name": "string", "role": "teacher"}` ——
> 不替换就 Execute，建出来的账号手机号就叫 `string`，之后你用 `13800000002`
> 怎么登都是「手机号或密码不正确」，重置密码也救不回来。2026-11-24 就是这么卡住的。

**应该看到**：状态 `201`，返回里 `initial_password` 是 **`00000000`**（固定值，不用抄）。

**然后**：用「账号只停用不删除」那条规则验证 —— 再点一次 Execute，
应该返回 `400`「手机号 13800000002 已被占用」。

## A6 · 老师首次登录

**操作**：退出登录 → 用 `13800000002` + `00000000` 登录

**应该看到**
- 同样被强制改密，改完进「课程」页
- 底栏**只有 4 个 tab**：课程 / 班级 / 学生 / 我的 —— **没有「合同」**
- 手动在地址栏输 `http://localhost:5173/contracts` → **自动被送回来**，落在课程页（不报错、不白屏）

> 同一个守卫还管着审批待办页，`http://localhost:5173/lessons/approvals` 老师打开也一样被送回来。

## A7 · 停用账号

**操作**：切回超管 → 到 `/docs` 调 `DELETE /api/admin/users/{id}`（老师那个 id）→ 再切回老师账号刷新

**应该看到**：刷新后回到登录页；再登录时提示「账号已停用，请联系管理员」，进不去。
**重点**：账号**没有消失**，`GET /api/admin/users` 里还能查到它，`is_active` 变成 `false`。

**再启用**：调 `PATCH /api/admin/users/{id}`，body `{"is_active": true}`

**应该看到**（这是 2026-11-24 定的新规则）：
- **密码自动打回 `00000000`**，用他上次自己改的那个密码登**不进去**
- 用 `00000000` 登 → 又能进，但**再次被要求改密**
- 也就是说「启用」本身就是一次重置，管理员不用再单独点重置

> ⚠️ 只有**真的从停用变启用**才重置。已经启用的账号你去改个姓名，
> 密码**不能**跟着变 —— 否则编辑资料等于悄悄重置别人密码。

## A8 · 连错 5 次锁 1 小时

**操作**：拿**测试老师**那个号（`13800000002`）登录，**故意输错密码 5 次**

**应该看到**
- 第 1–4 次：「手机号或密码不正确，还能再试 N 次」—— **N 每次减 1**（4 → 3 → 2 → 最后 1 次会单独提醒）
- **第 5 次**：提示变成「**密码错误次数过多，账号已锁定，请 60 分钟后再试**」
- 这时候**输对密码也进不去**，还是那句锁定提示（锁着的时候服务器压根不验密码）

**怎么解锁**（测完必须做，不然 B 组用不了这个号）：
超管到 `/docs` 调 `POST /api/admin/users/{id}/reset-password` → 密码回到 `00000000`、锁定一并解除
→ 用 `00000000` 登录 → 再改一次密码。

> 以后再锁了都是这个办法：管理员重置一次即可，不用等 1 小时。

- 老师那边：课程详情里显示「已通过 —— 申请改为 …」

## H5 · 驳回

**操作**：换回老师 → 再对另一节课提一条申请 → 换管理员 → 待审批页 → 点「驳回」→ 理由留空 →「确认驳回」

**应该看到**
- 驳回面板的输入框占位是「驳回理由（可以不填）」—— **不填也能驳回**
- 通过后提示「已驳回：<班级>」
- 老师那边**课程时间没变**，详情里显示「已驳回」，**没有**「驳回理由」那行（因为没填）

**再来一次**，这次驳回理由填 `那天老师请假` → 老师那边显示「驳回理由：那天老师请假」。

## H6 · 撤回

**操作**：老师 → 再提一条申请 → 点「撤回申请」

**应该看到**
- confirm：「撤回这条改期申请？撤回后可以重新提交。」
- 提示「已撤回改期申请」
- 状态变「已撤回」，**「申请改期」按钮又出来了**（可以重新提）

## H7 · 申请挂着的期间课被完成了 → 409

**操作**
1. 老师对一节**今天**的课提一条改期申请
2. 管理员把**这同一节课**先「完成上课」（填内容 + 扣课时）
3. 管理员回到待审批页 → 点「通过」

**应该看到**：**红字报错**（409），大意「这节课已经不是「已排课」了 / 请刷新后重试」，
**课程时间不会被改**。

> 为什么必须拦：那时候课时已经扣了、工资表上已经有这一节了，再改时间就是对不上的账。
> 这种申请只能**驳回**。

## H8 · 老师打不开待审批页

**操作**：老师账号手输 `http://localhost:5173/lessons/approvals`

**应该看到**：被送回来落在课程页，不报错。

## H9 · 「我的改期申请」看全部历史

**操作**：老师 →「我的」tab →「我的改期申请」→「查看 ›」

**应该看到**

  （有的话）驳回理由、`提交于 …`（处理过的还有 ` · 管理员 处理于 …`）

> 这正是 2026-10-29 修的那个问题：课程详情页只显示**最近一条**，提过两次之后前一条就"消失"了 ——
> 它一直在库里，这里能看全。

## H10 · 申请超过 10 条要翻页
